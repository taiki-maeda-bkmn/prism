# Prism implementation plan

## First working desktop release

Build the brief in `AGENTS.md` as a local desktop application. Notes remain ordinary Markdown files in a folder chosen by the user. Electron supplies the native transparent window, and React with CodeMirror supplies the editing interface.

- [x] Desktop foundation: isolated renderer, narrow filesystem bridge, native folder picker, window controls, and a starter notebook.
- [x] [Desktop session lifecycle](docs/session-lifecycle.md): cancel network waits on accepted close, drain file writes and release library ownership, recover hidden windows, provide a native crashed-editor close prompt, and stop failed launcher startups.
- [x] [Remember window placement](docs/window-placement.md): restore normal size and maximized state across launches, restore position on native Windows/macOS/X11, fit disconnected-monitor bounds to a connected work area, and reopen visibly after a minimized quit. Native Wayland placement is compositor-controlled. The WSLg host-position helper was removed after real mouse-input checks exposed a coordinate mismatch.
- [ ] [Exact WSLg position restoration](docs/window-placement.md#follow-up-exact-position-on-wslg): require supported compositor-aware placement and real Windows-pointer validation before restoring this capability. Existing host-position preferences remain untouched.
- [x] Note workspace: folder navigation, search, create, explicit save, refresh, conflict detection, and protection for unsaved edits when closing or switching folders.
- [x] Markdown: source, split preview, and reading modes; syntax highlighting; safe rendering; wiki links and Markdown file links.
- [x] Connected notes: clickable graph, backlinks, and navigation between notes.
- [x] Appearance: true background transparency with adjustable opacity, legible text, and persistent preferences.
- [x] [Keep background video playing](docs/background-video.md) behind native Windows transparency: advertise native translucency before showing a window and notify Windows when appearance changes, so browsers do not incorrectly classify visible video as covered. Opaque mode and 100% background opacity retain normal occlusion behavior.
- [x] Delivery: filesystem/link tests, desktop interaction checks, documentation, CI, and a pull request with Copilot review requested.

## Scope and follow-up

The new requirements in `AGENTS.md` are being implemented one at a time:

- [x] [Adjustable Markdown layout](docs/markdown-layout.md): independent heading, hint, save-confirmation, and topic-tool visibility; compact spacing and a More writing space preset. Keep mode switching, snippets, Save, and tabs accessible, persist preferences, and resize existing editor/reader sessions.
- [x] [Grouped document tabs](docs/document-tabs.md): open Markdown notes and PDFs in one wrapping tab area, organize mixed documents into collapsible topics, and remember tab metadata per notebook. Explicit dirty-note closing preserves drafts and save-conflict checks. Read & write keeps each pane independent; three retained PDF readers bound memory while evicted tabs keep lightweight reading coordinates.
- [x] [Markdown folders, first increment](docs/markdown-folders.md): show real empty and nested directories, filter/search notes by folder, remember the selection per notebook, create folders, and choose a destination for new notes. Inventory merges preserve drafts, undo, PDFs, and save-conflict baselines. Existing-note moves, link repair, folder rename, and drag/drop remain broken down as follow-ups.
- [x] [Independent PDF opacity](docs/pdf-reading-workflow.md#adjust-pdf-transparency): a saved 25–100% PDF reading-area control in Layout works under the existing Transparent window switch. Keep app backgrounds, toolbars, and sidebar appearance independent, including solid app backgrounds beside a translucent PDF. CSS compositing retains the PDF canvas, page/zoom/scroll, and drafts; native Windows translucency follows the actual visible PDF as well as app backgrounds.
- [x] [Adjustable PDF layout](docs/pdf-reading-workflow.md#adjust-the-pdf-reading-layout): show or hide the document heading, page toolbar, library search, Linked notes, and bottom navigation independently. Compact spacing and a More reading space preset reclaim vertical space while retaining reachable Layout, Library, and back controls. Resize the wide library sidebar by pointer or keyboard; saved preferences survive restart and compact-pane fallback. Keep reader sessions, page/zoom/scroll, and note drafts intact in both launchers.
- [x] Color customization: accent, page background, and text controls, saved locally, with reset and support for the existing transparent window.
- [x] Theme customization: Prism, Paper, and Sci-fi styles with coordinated palettes, typography, and controls; custom colors are remembered per theme.
- [x] [Import VS Code colors](docs/vscode-appearance.md): preview the configured default-profile theme or a JSON/JSONC theme file, then apply page, text, and accent colors to the current Prism palette. Named profiles, fonts, syntax tokens, and richer interface color mapping remain separate increments.
- [x] Recover VS Code's last-used saved theme when configured-theme discovery fails. A bounded private database snapshot preserves the original profile; current customizations follow the saved theme's identity. The preview identifies the recovered source, errors omit internal IPC details, and normal shutdown drains snapshot cleanup.
- [x] Built-in snippets with Tab completion: headings, tasks, quotes, code blocks, tables, links, and wiki links, with editable fields and an in-app guide.
- [x] Custom snippets: add, edit, and delete reusable Markdown templates in the Snippets dialog, with unique shortcuts, editable fields, block/inline context, local persistence, and immediate updates without replacing the editor or its undo history.
- [ ] Switchable direct editing in the rendered Markdown view: [stage 1](docs/live-editing.md) adds Live editing for headings and text formatting; follow-ups add editable highlighted code blocks, interactive task checkboxes, rendered links and lists, and tables with source reveal, including nested tables. Direct cell editing remains a separate stage.
- [x] Live list presentation: render nested bullets and sequential ordered numbers on inactive lines; clicking a marker or selecting its line exposes the exact source. Preserve task checkboxes, source indentation, editor behavior, and Markdown bytes.
- [x] Live links: render Markdown, reference, autolink, and wiki labels; Ctrl+left-click opens notes, heading fragments, web pages, and email links. Command+click also works. Ordinary clicks reveal editable source; table links share the same navigation gesture.
- [x] [Live tables](docs/live-tables.md): render top-level and quote/list-nested GFM tables with alignment, formatting, and cell math; click a cell to edit exact source, with keyboard access, scrolling, snippets, undo, and unchanged Markdown saves. Preserve container prefixes, nesting order, list numbering, and source positions after preceding edits.
- [x] [Math rendering](docs/math-rendering.md): offline inline and display equations in Split, Read, and Live, with source editing, invalid-formula recovery, and unchanged Markdown saves.

Duplicates preserve their existing folder and metadata; mixed batches report partial results. Both hosts share the bounded native-file bridge, busy/modal guards, compact navigation, and original-file preservation.
- [x] PDF tag suggestions in document details: match existing library tags as you type, with mouse and keyboard selection, case-insensitive duplicate exclusion, Japanese input support, and completion at the cursor within comma-separated tags. Custom tags and explicit save/cancel remain available in both launchers.
- [x] Swap PDF and Markdown sides in **Read & write**. **Swap sides** retains each pane's width, scroll, editor state, and unlocked reader session; DOM order follows the visual order. Mouse and arrow-key resizing follow physical direction in either order. Pane order is saved separately from the existing width preference and survives narrow-window fallback and restart. Compact title-bar controls remain reachable at large text sizes.
- [x] [Investigate PDF performance](docs/pdf-performance.md) and remove confirmed redundant redraws: numeric zoom ignores viewport resizing, fit width settles for 120 ms while retaining the current page, and replaced canvases release their backing buffers. A reproducible opt-in profiler records synthetic workloads without opening user data. Graphics acceleration, page caching, thumbnail priority, and Markdown typing costs remain separate follow-ups.
- [x] [Reduce Markdown editing work](docs/markdown-performance.md): Source and Live collect navigation metadata without compiling unused full-document previews. Preserve raw HTML outline compatibility, math labels, heading links, visible previews, undo, and exact saves. An opt-in profiler records typing, cursor movement, scrolling, and discarded formula conversions in a disposable Japanese/math notebook; graph/parser and combined-PDF costs remain follow-ups.
- [x] [Recover reproduced maximized Markdown scrolling lag](docs/markdown-scrolling.md): after a compositor shared-memory allocation failure disabled WSLg redirection, an approved WSL restart reopened Prism and restored redirection/client negotiation. The same 3840×2088 scrolling test improved from 133–268 ms p95 frame gaps to 22–28 ms across Source/Live/Read. Physical scrolling confirmation and recurrence investigation remain follow-ups; directory metadata errors alone do not diagnose transport failure.

PDF reading includes persistent Previous/Next controls below the page, click-to-focus keyboard paging, and Space/Shift+Space screen scrolling. Mouse-wheel and trackpad scrolling stay within the current page and never turn pages at its edges. The former wheel-turn handler and gesture gate have been removed. Keyboard input remains scoped to the page viewport. Both launchers share this behavior. See [page navigation](docs/pdf-reading-workflow.md#turn-pages-from-the-reading-area).

An open P2 review finding concerns concurrent replacement of nested directories between validation and filesystem access. A portable fix requires directory-handle operations across the filesystem layer. Per the brief's instruction to break down large next actions, [filesystem races](docs/filesystem-races.md) records the implementation stages and acceptance tests. This finding remains unresolved; passing current CI does not cover this race.

This release prioritizes editing, reading, and navigating local notes. Sync services, plugins, rich-text editing, attachment management, automatic link updates on rename, and signed installers are later requirements. The repository will include commands for building and running the desktop app.

Transparent windows depend on the host compositor. The implementation uses a transparent native window and translucent background colors, without blurring the windows behind it. The title bar uses native maximize/restore so the window manager reserves the taskbar area and restores the previous bounds. Linux/macOS allow native resizing; Windows retains fixed normal bounds. Compositor behavior still needs physical platform verification.

The WSLg launcher selects native Wayland before Electron initializes when the local Wayland socket is available. This avoids Xwayland's displaced content in maximized borderless windows. Explicit backend choices and remote or isolated X displays are preserved. Showing the loaded page explicitly also avoids an initially hidden transparent Wayland window. A WSLg Wayland resize schedules a full repaint to reduce stale surfaces after resize. Opt-in tests check actual Windows host pixels and monitor work-area bounds through maximize, restore, and repeated minimization. On WSLg Wayland, returning focus also clears a stale minimized state before repainting; without that recovery, a window restored from the Windows taskbar can keep showing its last frame while appearing unresponsive. The recovery retains the native maximized state and the existing renderer, drafts, and undo history.

WSLg startup position is now left to the compositor. The removed Windows helper moved the visible host without updating compositor input coordinates; a restored window could be enabled and visible while mouse clicks never reached its controls. Normal size/maximized persistence and the existing repaint/focus recovery remain. The regression check sends real Windows mouse input, because earlier geometry tests used Playwright clicks and missed this route.

## Workflow

Implementation branch: `feat/prism-desktop`. Commit and push changes automatically, request Copilot review, address actionable review feedback, and leave the pull request open. Do not merge automatically.

Run appropriate local build, type, unit, and desktop checks. Per the user's instruction, do not check or wait for GitHub CI unless explicitly requested for the current task. Before reporting the work complete, check the Codex review against the current PR commit. Wait for the review summary to show that commit as completed, address any new findings, and check for unresolved threads. A new push requires checking the new commit's review again; resolved comments on an earlier commit do not complete this check.
