# Prism implementation plan

## First working desktop release

Build the brief in `AGENTS.md` as a local desktop application. Notes remain ordinary Markdown files in a folder chosen by the user. Electron supplies the native transparent window, and React with CodeMirror supplies the editing interface.

- [x] Desktop foundation: isolated renderer, narrow filesystem bridge, native folder picker, window controls, and a starter notebook.
- [x] Note workspace: folder navigation, search, create, explicit save, refresh, conflict detection, and protection for unsaved edits when closing or switching folders.
- [x] Markdown: source, split preview, and reading modes; syntax highlighting; safe rendering; wiki links and Markdown file links.
- [x] Connected notes: clickable graph, backlinks, and navigation between notes.
- [x] Appearance: true background transparency with adjustable opacity, legible text, and persistent preferences.
- [x] Delivery: filesystem/link tests, desktop interaction checks, documentation, CI, and a pull request with Copilot review requested.

## Scope and follow-up

The new requirements in `AGENTS.md` are being implemented one at a time:

- [x] Color customization: accent, page background, and text controls, saved locally, with reset and support for the existing transparent window.
- [x] Theme customization: Prism, Paper, and Sci-fi styles with coordinated palettes, typography, and controls; custom colors are remembered per theme.
- [x] Built-in snippets with Tab completion: headings, tasks, quotes, code blocks, tables, links, and wiki links, with editable fields and an in-app guide.
- [x] Custom snippets: add, edit, and delete reusable Markdown templates in the Snippets dialog, with unique shortcuts, editable fields, block/inline context, local persistence, and immediate updates without replacing the editor or its undo history.
- [ ] Switchable direct editing in the rendered Markdown view: [stage 1](docs/live-editing.md) adds Live editing for headings and text formatting; follow-ups add editable highlighted code blocks, interactive task checkboxes, rendered links and lists, and tables with source reveal, including nested tables. Direct cell editing remains a separate stage.
- [x] Live list presentation: render nested bullets and sequential ordered numbers on inactive lines; clicking a marker or selecting its line exposes the exact source. Preserve task checkboxes, source indentation, editor behavior, and Markdown bytes.
- [x] Live links: render Markdown, reference, autolink, and wiki labels; Ctrl+left-click opens notes, heading fragments, web pages, and email links. Command+click also works. Ordinary clicks reveal editable source; table links share the same navigation gesture.
- [x] [Live tables](docs/live-tables.md): render top-level and quote/list-nested GFM tables with alignment, formatting, and cell math; click a cell to edit exact source, with keyboard access, scrolling, snippets, undo, and unchanged Markdown saves. Preserve container prefixes, nesting order, list numbering, and source positions after preceding edits.
- [x] [Math rendering](docs/math-rendering.md): offline inline and display equations in Split, Read, and Live, with source editing, invalid-formula recovery, and unchanged Markdown saves.
- [x] Wider writing area: Live and Read fill the available pane in every theme, with responsive side padding and no fixed centered-column width.
- [x] Live cursor alignment after tables and display equations: keep block spacing inside CodeMirror's measured widget boxes so clicks target the displayed text.
- [x] Expandable note inspector: drag its left divider or use arrow keys to resize Outline, Connections, and Backlinks. Home or double-click resets the width. Saved widths survive restarts, focus mode, and graph navigation; smaller windows temporarily clamp the panel to preserve editing space and retain the existing responsive hide.
- [x] Rearrange the full graph by dragging individual vertices or using arrow keys. Connections follow the moved notes, clicks and Enter/Space still open notes, and manual positions survive navigation, edits, and refresh within the current notebook session. Reset layout restores automatic positioning; restart or notebook switching starts a fresh layout.
- [ ] Retain per-note editor history across note and full-graph navigation. Draft text is preserved today, but those transitions recreate the editor and reset undo; PDF workspace round trips to the same mounted note preserve history. A follow-up must bound retained editor state and preserve refresh/discard/notebook isolation.
- [x] [Integrate Prism PDF](docs/pdf-integration.md): core [stage 1](docs/pdf-stage-1.md), [stage 2](docs/pdf-stage-2.md), and [stage 3](docs/pdf-stage-3.md) are complete. **Read & write** provides resizable note/PDF panes, independent scrolling, focus-scoped shortcuts, retained drafts/readers, and narrow-window fallback. [Stable page links](docs/pdf-page-links.md) insert at the note selection and open the managed document/page; combined offline, restart, native-window, and error-recovery journeys verify the complete workflow. **Linked notes** adds current-notebook PDF backlinks with cited-page navigation and live draft updates. The full graph now includes cited PDFs with distinct nodes, a **Show PDFs** filter, stable manual positions, and missing-document recovery. The compact inspector shows up to four direct note/PDF neighbors, with overflow into the full graph and explicit title loading. Combined offline navigation, same-note PDF undo, draft retention, save/restart, and notebook replacement checks cover the connection workflow. See the [session guide](docs/pdf-reading-workflow.md). Preserve existing data and keep the sibling `pdfmanager` project independent during the transition. AI assistance and OpenAI API integration are excluded.

Text size now defaults to 120% and remains adjustable in Appearance. Built-in and custom slash snippets support Tab completion in Source, Split, and Live modes. Richer Live blocks remain separate follow-ups.

PDF reading now includes persistent Previous/Next controls below the page, deliberate wheel turns at page edges, click-to-focus keyboard paging, and Space/Shift+Space screen scrolling. Wheel momentum stays within one page turn per gesture; keyboard input remains scoped to the page viewport. Both launchers share this behavior. See [page navigation](docs/pdf-reading-workflow.md#turn-pages-from-the-reading-area).

An open P2 review finding concerns concurrent replacement of nested directories between validation and filesystem access. A portable fix requires directory-handle operations across the filesystem layer. Per the brief's instruction to break down large next actions, [filesystem races](docs/filesystem-races.md) records the implementation stages and acceptance tests. This finding remains unresolved; passing current CI does not cover this race.

This release prioritizes editing, reading, and navigating local notes. Sync services, plugins, rich-text editing, attachment management, automatic link updates on rename, and signed installers are later requirements. The repository will include commands for building and running the desktop app.

Transparent windows depend on the host compositor. The implementation uses a transparent native window and translucent background colors, without blurring the windows behind it. The title bar uses native maximize/restore so the window manager reserves the taskbar area and restores the previous bounds. Linux/macOS allow native resizing; Windows retains fixed normal bounds. Compositor behavior still needs physical platform verification.

The WSLg launcher selects native Wayland before Electron initializes when the local Wayland socket is available. This avoids Xwayland's displaced content in maximized borderless windows. Explicit backend choices and remote or isolated X displays are preserved. Showing the loaded page explicitly also avoids an initially hidden transparent Wayland window. A WSLg Wayland resize schedules a full repaint to reduce stale surfaces after resize. Opt-in tests check actual Windows host pixels and monitor work-area bounds through maximize, restore, and repeated minimization. On WSLg Wayland, returning focus also clears a stale minimized state before repainting; without that recovery, a window restored from the Windows taskbar can keep showing its last frame while appearing unresponsive. The recovery retains the native maximized state and the existing renderer, drafts, and undo history.

## Workflow

Implementation branch: `feat/prism-desktop`. Commit and push changes automatically, request Copilot review, address actionable review feedback, and leave the pull request open. Do not merge automatically.

Run appropriate local build, type, unit, and desktop checks. Per the user's instruction, do not check or wait for GitHub CI. Before reporting the work complete, check the Codex review against the current PR commit. Wait for the review summary to show that commit as completed, address any new findings, and check for unresolved threads. A new push requires checking the new commit's review again; resolved comments on an earlier commit do not complete this check.
